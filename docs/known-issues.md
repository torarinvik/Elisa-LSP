# Elisa LSP known issues

This file is the release-facing list of limitations that are intentionally
visible in `docs/feature-manifest.json`. It is checked against the current
build and compiler provenance; an item is not a promise that the missing
capability is silently approximated.

| Area | Status | Current behavior | Gate before changing it |
|---|---|---|---|
| Compiler backend | optimizer-integration compiler snapshot on supported stage0; stage1 backend remains unqualified | The current Darwin/arm64 release uses compiler HEAD `d4b40e36770d89973de1b8df93f8e0bcd091ae6a`, source fingerprint `32e2a49805f25ad79de69118c741aa75ee6e0ad9856ea27af9b0a0818e927638`, supported stage0 SHA-256 `5f2c14780bb91b25feeef3e4dce685ba9199d264ab75f335b064741a138ea84e`, and `-O2 -fno-builtin -Wl,-v`. The selected integration includes owner-indexed lookup chains, O(1) collection-stack lookup, and narrower enum/module visits. Stage1 parity and performance are unqualified for this compiler source fingerprint. | `bench/compiler-upgrade-latest-541-stage1-2026-10-05-build-only.json`, `bench/current-compiler-d4b40e3-2026-10-06.json`, `scripts/compiler_upgrade_gate.py`, `scripts/check_build_freshness.py` |
| Frontend checkout | exact current source fingerprint pinned in the release manifest | The release manifest records clean compiler HEAD `d4b40e36770d89973de1b8df93f8e0bcd091ae6a` and source fingerprint `32e2a49805f25ad79de69118c741aa75ee6e0ad9856ea27af9b0a0818e927638` from `/private/tmp/elisa-lsp-compiler-latest-d4b40e3`, with `compiler_dirty=false`. The LSP release was built from this immutable source snapshot; changes to compiler source bytes require rebuilding and rerunning the suite. | B01, scripts/check_build_freshness.py, test/frontend_contract_test.sh |
| Hover | limited | Declarations and exact parameter/local bindings use retained analysis data; parameters and locals with explicit annotations show source type keyed by compiler `BindingId`, validated against the accepted snapshot and bounded to 2,048 bytes per binding and 65,536 bytes per document. If a binder position is imprecise, source recovery accepts only a unique same-line `Ident:` token; otherwise the annotation is omitted. Unannotated bindings remain role/name-only because inferred type data is not yet stable in the adapter. A compiler-registered enum variant is shown with its owner only when its spelling has one owner and does not collide with an ordinary declaration in the current analysis; ambiguous or colliding variants and overloaded declaration names return no hover because exact enum-variant occurrence identities and overload selection data are not retained. Uniquely retained top-level functions show their exact source signature, including declared parameters/defaults, generic binders, return annotation, and declared effects. Loop-capture hover is limited to the pipe-delimited capture list and returns its exact negotiated range; nested/default-expression parsing still uses a simple delimiter scan. Documentation, defining modules, and contracts are not yet surfaced. | F01, test/general_hover_test.sh |
| Cross-file analysis | unavailable | Providers operate on the accepted open-document snapshot; workspace dependency resolution, unsaved dependency overlays, and workspace-wide diagnostics are not implemented. | W01–W04 and G04 |
| Completion and rename | limited | Completion is explicitly incomplete; InsertReplaceEdit, argument snippets, safe `(` commit characters, and parameter-name label details are emitted only when their respective `CompletionItem` capabilities are declared. `completionItem/resolve` adds parameter-list detail for a unique retained same-file function signature only while the item's canonical URI, version, and open-document generation match the current ready snapshot; stale items remain unchanged, and client-owned fields round-trip. Exact declaration-backed locals are offered within function and nested indentation blocks and stop at an outdent; parser-provided scope ranges, documentation and return-type resolution, imported/member/workspace candidates remain unimplemented. Rename is advertised only for exact same-file parameter/local BindingIds, emits versioned edits, and rejects a new spelling already present anywhere in the source; scratch re-analysis and cross-file edits are not implemented. | F05, F07, F09 |
| Definition | limited | Unique same-file top-level functions and exact parameter/local BindingIds resolve to declarations. Clients declaring `textDocument.definition.linkSupport` receive `LocationLink[]` with exact origin and target token spans; other clients receive `Location`. Overloaded/module-scoped functions, other declaration categories, enclosing declaration ranges, and cross-file targets remain unsupported. | F03, A02, W02 |
| Document highlights | limited | Exact same-document function and parameter/local identities are highlighted. Declarations use `Text`, resolved reads use `Read`, and only direct identifier `<-` targets use `Write`; the compiler does not yet expose authoritative roles for indirect/member/index writes. | F04, A02 |
| Formatting, code actions, inlay hints | unavailable | The server does not rewrite source or suggest semantic changes until a lossless syntax/trivia and safe-edit gate exists. | E01–E03 |
| Scheduling and cancellation during analysis | experimental boundary | A one-shot POSIX worker contains compiler faults and has a deadline, but synchronous dispatch cannot read a newer request while analysis is running. A matched in-process comparison estimates 27 ms fixed worker-boundary overhead on small files and 38 ms for a 2,048-constant file on one Darwin/arm64 host; retain isolation while Q01 designs responsive, restartable worker lifecycle behavior. | Q01–Q03; `bench/analysis-worker-overhead-2026-10-06.json` |
| Platform support | Darwin/arm64 validated for the 2026-10-06 release input; aggregate suite passes | The current release uses compiler HEAD `d4b40e36770d89973de1b8df93f8e0bcd091ae6a`, source fingerprint `32e2a49805f25ad79de69118c741aa75ee6e0ad9856ea27af9b0a0818e927638`, stage0 SHA-256 `5f2c14780bb91b25feeef3e4dce685ba9199d264ab75f335b064741a138ea84e`, LSP input hash `f9d1a3143d58a0cf7a8c9b0de5e735685aa08cbd0262f08630d0316a69ba2a92`, 624-file include-closure hash `09b6568c62e7ed97a517469a4296eb87043ea512a846862f4da795cfcfc9aa1f`, object hash `c1ce202fdf85bdbbbcce1e3f5e86eb96b49e9651742e24c0fee07e04aba65a81`, and executable hash `be2ed3ade90e60d9e5b078097014312cfcb851fe8c5521b7690329c0b60cc182`. Strict freshness and the exact-input canonical suite pass (`81/81`). Linux evidence in `bench/platform-validation-Linux-aarch64.json` covers an earlier LSP input and does not establish this build. Windows has no transport/path/process adapter. | scripts/platform_validation.py, R04 |
| Custom semantic-token rendering | interoperable fallback | Standard-token fallback and four standard modifiers are negotiated. Client-specific colors and Elisa-specific modifiers require an editor rendering contract. | H01 and R01/R02 |
| Filesystem identity | lexical overlay policy | The standalone server does not read the filesystem. Case sensitivity and symlink physical identity are measured only by the future workspace resolver, which fails closed when unknown. | W02/W04 |

Every row has a machine-readable counterpart or explicit planned gate. When a
compiler or client changes, update the corresponding manifest entry, add a
focused regression, and retain the previous artifact provenance for rollback.
